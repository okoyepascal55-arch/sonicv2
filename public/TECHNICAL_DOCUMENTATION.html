#System Overview

The Sonic Group website is a React 19 single-page application (SPA) built with Vite 7. It serves as the public marketing site for Sonic Group — a full-service retail activation agency for the DACH market — and includes an integrated Content Management Dashboard that lets administrators update images and copy across every page without touching source code.

Frontend

React 19 SPA, TypeScript 5.8, Tailwind CSS 3, Vite 7

Backend

Supabase — PostgreSQL, Storage, Edge Functions (Deno)

Hosting

Vercel — auto-deploys from main branch, global CDN

Forms

Web3Forms API delivering to info@sonic-group.de

SPA note: All routing is client-side. Vercel rewrites all paths to /index.html so direct URL access and page refresh work correctly.

Key Architectural Decisions

1. Client-first, serverless

No custom backend server. All business logic runs in the browser or in Supabase Edge Functions (Deno). Vercel's CDN handles global delivery.

2. Optimistic localStorage + Supabase sync

Media and text overrides are stored in localStorage for instant reads, and asynchronously synced to Supabase's media_store PostgreSQL table. The site renders immediately even without network access.

3. Private image bucket + Edge Function proxy

Uploaded images are stored in a private Supabase Storage bucket. The media-proxy Edge Function mints 7-day signed URLs per request. Image references use the __storage__:path token; resolveImageUrl() converts this at render time.

4. Code-split pages via React.lazy()

Every page is wrapped in React.lazy(). Vite splits each page into its own JS chunk, minimising the initial bundle.

#Routing

Routing is handled by React Router 7 using BrowserRouter with a configurable basename (injected via the __BASE_PATH__ Vite define constant, default /). Route definitions live in src/router/config.tsx.

The root App.tsx wraps all routes with: FaviconController, SchemaOrg, CalendlyWidget, SkipLink, ScrollToHash, and conditionally hides Navigation / Footer on /dashboard.

Page Transition

AnimatedRoutes performs a 150ms opacity fade-out → content swap → fade-in on route change, plus an instant window.scrollTo({top:0}) with a 10ms safety timeout to override browser scroll restoration.

#State Management

No global state library is used. State is managed through:

  • React useState / useCallback / useMemo — local UI state within components
  • localStorage — persistent store for media and text overrides (written by CMS, read by all pages)
  • Custom window events — media-store-update notifies listening components when the store changes
  • Supabase DB — cloud source of truth, synced to/from localStorage
  • sessionStorage — dashboard auth flag (sonic_admin_auth)

#Media Store

src/lib/mediaStore.ts (~2,449 lines) is the core image content engine. It manages all image data across every page section.

Data Model

interface MediaItem {
  url:     string;   // "__storage__:path"  or external URL
  caption: string;   // alt text / label
  wide?:   boolean;  // span full-width layout
}

type MediaSections = { [sectionKey: string]: MediaItem[] };

Storage Architecture (layered overrides)

  1. Default images — hardcoded in mediaStore.ts (fallback)
  2. localStorage overrides — written by dashboard, read instantly on every page load
  3. Supabase DB sync — full overrides object written as a single JSONB row (id=1) in media_store

Image URL Resolution

resolveImageUrl("__storage__:dashboard/123-photo.webp")
  // → https://<project>.supabase.co/functions/v1/media-proxy?path=dashboard%2F123-photo.webp

resolveImageUrl("https://external.com/image.jpg")
  // → "https://external.com/image.jpg"  (pass-through)

#Edge Functions

media-proxy

Located at supabase/functions/media-proxy/index.ts. Deno runtime. Converts a storage file path into a signed URL, keeping the bucket private.

Request

GET /functions/v1/media-proxy?path=dashboard%2F1234-photo.webp

Responses

ConditionResponse
Success302 Location: <signed-url> — Cache-Control: 1h browser / 24h CDN
Missing path param400 JSON error
Missing env secrets500 misconfiguration error
Storage failure500 with storage error message

Signed URLs are valid for 7 days (604,800 s). Deploy command:

supabase functions deploy media-proxy --no-verify-jwt

Required secrets (set in Supabase Dashboard → Edge Functions → Secrets):

  • SUPABASE_SERVICE_ROLE_KEY — never exposed to client
  • SUPABASE_URL — injected automatically by Supabase

#Contact / Forms

All forms submit to info@sonic-group.de via the Web3Forms API (https://api.web3forms.com/submit). Managed in src/lib/contact.ts.

  1. User submits a form
  2. submitContactForm(data) is called
  3. If VITE_WEB3FORMS_KEY is set: POST to Web3Forms → email delivered to inbox
  4. If key is missing: fallback opens a mailto: link with pre-filled subject & body
Privacy: Web3Forms retains no form data beyond delivery. No Formspree or third-party routing involved.

#Security Notes

Exposed client-side (by design)

  • Supabase anon key — designed to be public; access controlled by RLS
  • Supabase project URL
  • Web3Forms access key (rate-limited per key by Web3Forms)
  • Dashboard credentials (admin/admin, sonic/sonic2026) — in the JS bundle

Never exposed client-side

  • Supabase service role key — only in Edge Function secrets
  • Any database tables beyond media_store and dashboard/ prefix storage
Dashboard credentials are in the JS bundle. For production hardening, migrate to Supabase Auth (email/password or magic link) to move credential validation server-side.
